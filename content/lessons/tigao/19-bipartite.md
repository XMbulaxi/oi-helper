# 二分图

> **学完能做到**：用染色法判断二分图；用匈牙利算法求二分图最大匹配；把"行列""人和物"的配对问题建模成二分图。
> **前置知识**：DFS、BFS、图的存储。

---

## 1. 什么是二分图

如果能把图的点分成两组，使**每条边都连接不同组的两个点**（同组之间没有边），这个图就是**二分图**。

**等价条件**：图中**没有奇数长度的环**。

## 2. 染色法判断二分图

从任意点开始 DFS/BFS，给它染色 1，它的邻居染色 2，邻居的邻居染色 1……如果发现一条边两端颜色相同，就不是二分图。

```cpp
int color[N];   // 0 = 未染色，1 / 2 = 两种颜色

bool dfs(int u, int c) {
    color[u] = c;
    for (int v : g[u]) {
        if (color[v] == c) return false;                 // 冲突
        if (color[v] == 0 && !dfs(v, 3 - c)) return false;
    }
    return true;
}
// 图可能不连通，对每个未染色的点都要调用
```

### 例：封锁阳光大学（P1330）

在一些点上放河蟹，每条边恰好有一个端点放了河蟹（不能两端都放，也不能都不放），问最少放几只。

"每条边恰好一个端点放"——这正是二分图染色！对每个连通块染色，选颜色数量较少的那一组放河蟹。如果某个连通块不是二分图，输出 Impossible。

### 例：关押罪犯（另一种做法）

二分答案 x：怨气 > x 的罪犯对必须分到不同监狱。把这些对连边，判断是否是二分图。

## 3. 二分图匹配

**匹配**：选一些边，使任意两条边**没有公共端点**。**最大匹配**：边数最多的匹配。

例：左边是 n 个人，右边是 m 份工作，边表示"这个人能做这份工作"，每人最多一份、每份最多一人，最多安排几个人？

## 4. 匈牙利算法

### 思路：找增广路

依次给左边每个点 u 找对象。对于 u 的每个邻居 v：

- 如果 v **还没有匹配**，直接匹配。
- 如果 v 已经和 u' 匹配了，**问 u' 能不能换一个**（递归给 u' 找别的对象）。如果能，v 就让给 u。

```cpp
int match[N];     // match[v] = 右边点 v 当前匹配的左边点，0 表示没匹配
bool vis[N];      // 本轮中右边点 v 是否已经被尝试过

bool find(int u) {
    for (int v : g[u]) {
        if (vis[v]) continue;
        vis[v] = true;
        if (match[v] == 0 || find(match[v])) {
            match[v] = u;
            return true;
        }
    }
    return false;
}

int hungarian(int n) {
    int ans = 0;
    for (int u = 1; u <= n; u++) {
        memset(vis, 0, sizeof(vis));   // 每个左边点开始前清空
        if (find(u)) ans++;
    }
    return ans;
}
```

复杂度 O(n × m)（n 是左边点数，m 是边数），n、m 几百到几千时没问题。

**vis 的作用**：在给一个左边点 u 找对象的这一轮中，每个右边点只尝试一次，避免死循环。

## 5. 建模

二分图匹配的难点在于**看出这是一个匹配问题**。

### 矩阵游戏（P1129）

N × N 的 01 矩阵，可以交换任意两行或两列。问能否使主对角线全是 1。

**分析**：交换行列不会改变"同一行（或同一列）的元素集合"。要让 (1,1), (2,2), …, (n,n) 都是 1，就要找到 n 个 1，它们**两两不同行、不同列**。

**建模**：左边是行，右边是列，(i, j) 是 1 就连边 i — j。问最大匹配是否等于 n。

> **"每行每列各选一个"** → 行和列建二分图。

### 假期的宿舍（P2055）

有的人是在校学生（有床），有的人回家（床空出来），还有外校来的人。认识的人可以睡对方的床。问需要住宿的人是否都能有床。

左边：需要床的人（不回家的在校生 + 外校生）。右边：床（在校生的床）。如果 a 认识 b（或 a 就是 b），a 可以睡 b 的床。求最大匹配是否等于需要床的人数。

## 6. 相关结论（了解）

- **König 定理**：二分图中，最小点覆盖 = 最大匹配。
- 最大独立集 = 点数 - 最大匹配。
- DAG 的最小路径覆盖 = 点数 - 拆点后二分图的最大匹配。
- 更大规模的匹配用网络流（Dinic），是 NOI 及以上的内容。

## 7. 易错点清单

1. 匈牙利算法中每个左边点开始前没清空 vis。
2. 染色时图不连通，只从一个点开始。
3. 左右两边点的编号混在一起，match 数组搞混。
4. 多组数据时没清空 match 和图。

## 9. 自测

1. 一个三角形（3 个点两两相连）是二分图吗？
2. 匈牙利算法中，"让 u' 换一个对象"是怎么实现的？
3. 矩阵游戏为什么可以转化为匹配？

<details><summary>答案</summary>

1. 不是，有长度为 3 的奇环。
2. 递归调用 find(match[v])，看 u' 能否在不使用 v 的情况下找到别的对象。
3. 行列交换不改变哪些 1 在同一行或同一列，问题等价于找 n 个两两不同行不同列的 1。
