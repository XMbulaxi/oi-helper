## 1. 真题的特点

NOIP / CSP-S 的题目很少是"裸模板"，通常是：

- **一个模型 + 一个优化**：二分答案 + 差分（借教室）、DP + 单调队列（跳房子）。
- **观察性质后变简单**：花匠（只需数拐点）、蚯蚓（三个队列天然有序）。
- **多个算法拼接**：Kruskal + LCA（货车运输）、二分 + LCA + 树上差分（运输计划）。

所以做真题的重点是：**先想清楚题目的本质，再选算法**。

## 2. 例题：借教室（NOIP2012，P1083）

n 天，每天有 rᵢ 间教室。m 份订单，第 j 份要在第 sⱼ 到 tⱼ 天每天借 dⱼ 间。按顺序处理订单，问第一份无法满足的订单是哪一份。

**思路**：

1. 如果前 k 份订单能满足，那么前 k-1 份也能满足 → **二分 k**。
2. check(k)：前 k 份订单都是"区间加"，用**差分**算出每天的需求，和 rᵢ 比较。O(n + m)。

总复杂度 O((n + m) log m)。

```cpp
bool check(int k) {
    fill(diff, diff + n + 2, 0);
    for (int j = 1; j <= k; j++) { diff[s[j]] += d[j]; diff[t[j] + 1] -= d[j]; }
    long long need = 0;
    for (int i = 1; i <= n; i++) {
        need += diff[i];
        if (need > r[i]) return false;
    }
    return true;
}
```

（也可以用线段树区间减 + 区间最小值，在线处理每份订单。）

## 3. 例题：选择客栈（NOIP2011，P1311）

n 家客栈有色调和最低消费，两人要住**色调相同**的两家，且两家之间（含）至少有一家最低消费 ≤ p 的咖啡店。求方案数。

**O(n) 做法**：从左到右扫描，记录**最近一个**消费 ≤ p 的位置 last。对于当前客栈 i（色调 c），能和它配对的是 last 及之前、色调为 c 的客栈。维护每种色调"在 last 之前出现的次数"即可。

## 4. 例题：花匠（NOIP2013，P1970）

一排花有高度，去掉一些花，使剩下的花高度**交替**升降（波浪形），求最多剩几盆。

可以 DP：f[i][0/1] 表示以 i 结尾、最后一步是上升/下降的最长长度。但更简单的**观察**：答案就是序列中"**拐点**"的个数 + 2（首尾）。连续上升的一段只需保留最高点，连续下降的一段只需保留最低点。注意相等的相邻元素要先去掉。

## 5. 例题：聪明的质监员（NOIP2011，P1314）

n 个矿石有重量和价值，选一个参数 W，检验值 = Σ（每个区间中重量 ≥ W 的矿石个数 × 这些矿石价值之和）。求 |检验值 - S| 的最小值。

1. W 越大，检验值越小 → 检验值关于 W 单调 → **二分 W**，找最接近 S 的位置（比较两侧的值）。
2. check(W)：用**前缀和**统计重量 ≥ W 的矿石个数和价值和，每个区间 O(1)。

## 6. 进阶题简介

- **换教室（NOIP2016，P1850）**：期望 DP + Floyd 最短路。f[i][j][0/1] 表示前 i 节课申请了 j 次、第 i 节课是否申请时的最小期望路程。
- **运输计划（NOIP2015，P2680）**：树上 m 条路径，可以把一条边权变为 0，使最长路径最短。二分答案 + LCA 求路径长度 + 树上边差分找所有超长路径的公共边。
- **天天爱跑步（NOIP2016，P1600）**：树上路径与观察员，需要把路径拆成上行和下行两段，用桶 + DFS 统计。是 NOIP 历史上最难的题目之一，作为最终挑战。

## 7. 考场策略

### 时间分配（4 小时，4 道题）

1. **前 15～20 分钟：读完所有题目**。估计每道题的难度，想好每道题的暴力做法。
2. **先做最有把握的题**，确保拿满分。
3. 对于没想到正解的题，**先写暴力拿部分分**，再想优化。
4. 最后 30 分钟：停止写新代码，检查文件名、输入输出、数组大小、long long。

### 部分分

题目一般会给出多档数据范围。看数据范围选算法：

| 数据范围 | 可以接受的复杂度 |
| --- | --- |
| n ≤ 10 | O(n!)、O(2ⁿ × n) |
| n ≤ 20 | O(2ⁿ × n) |
| n ≤ 100 | O(n³)、O(n⁴) 勉强 |
| n ≤ 1000 | O(n²)、O(n² log n) |
| n ≤ 10⁵ | O(n log n)、O(n √n) |
| n ≤ 10⁶ | O(n)、O(n log n) 要小心常数 |
| n ≤ 10⁹ 以上 | O(log n)、O(√n)、数学公式 |

**特殊性质的部分分**（树是一条链、所有数相等、k = 1……）往往能启发正解。

### 对拍

写好了正解，但不确定对不对？

1. 写一个**暴力程序** brute.cpp（简单、肯定正确，但慢）。
2. 写一个**随机数据生成器** gen.cpp。
3. 写一个对拍脚本，反复生成数据、比较两个程序的输出：

```bash
# Linux（考场一般是 Linux 环境）
for i in $(seq 1 1000); do
    ./gen > in.txt
    ./sol < in.txt > out1.txt
    ./brute < in.txt > out2.txt
    if ! diff -q out1.txt out2.txt > /dev/null; then
        echo "不一致！"; cat in.txt; break
    fi
done
```

```cpp
// gen.cpp：随机生成小数据
#include <bits/stdc++.h>
int main() {
    std::mt19937 rng(std::random_device{}());
    int n = rng() % 10 + 1;
    printf("%d\n", n);
    for (int i = 0; i < n; i++) printf("%d ", (int)(rng() % 100));
}
```

找到不一致的数据后，数据很小，可以手算或加输出调试。

### 常见失分原因检查清单

- [ ] 文件名、文件输入输出（`freopen`）是否按要求写对？
- [ ] 数组是否开够？多开一点但不要超内存。
- [ ] 该用 `long long` 的地方用了吗？乘法之前转换了吗？
- [ ] 多组数据时是否清空了数组和变量？
- [ ] 边界情况：n = 1、n = 0、所有数相同、答案为 0？
- [ ] 删掉了调试输出吗？
- [ ] 递归层数会不会太深？
- [ ] 本地用最大数据测过时间吗？

### 快速输入输出

数据量很大（10⁶ 以上）时：

```cpp
ios::sync_with_stdio(false);
cin.tie(nullptr);
// 之后不要混用 scanf/printf 和 cin/cout
```

或者手写快读：

```cpp
inline long long read() {
    long long x = 0, f = 1; char c = getchar();
    while (c < '0' || c > '9') { if (c == '-') f = -1; c = getchar(); }
    while (c >= '0' && c <= '9') { x = x * 10 + (c - '0'); c = getchar(); }
    return x * f;
}
```

## 10. 自测

1. 借教室为什么可以二分？
2. n ≤ 2000 时，O(n²) 能过吗？O(n³) 呢？
3. 对拍需要哪三个程序？

<details><summary>答案</summary>

1. 前 k 份订单能满足 → 前 k-1 份也能满足，可行性关于 k 单调。
2. O(n²) = 4×10⁶ 轻松通过；O(n³) = 8×10⁹ 会超时。
3. 要测的程序（正解）、暴力程序、随机数据生成器（再加一个对拍脚本）。
