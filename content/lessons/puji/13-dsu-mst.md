# 并查集与最小生成树

> **学完能做到**：用并查集快速合并集合、查询两个元素是否同属一个集合；用 Kruskal 和 Prim 求最小生成树。
> **前置知识**：图的存储、排序。

---

## 1. 并查集解决什么问题

"A 和 B 是亲戚，B 和 C 是亲戚，问 A 和 C 是不是亲戚？"

需要支持两种操作：

- **合并**：把两个人所在的家族合并成一个。
- **查询**：两个人是否在同一个家族。

用 DFS 每次查询都要遍历，太慢。**并查集**让这两种操作都接近 O(1)。

## 2. 并查集的原理

每个集合用一棵树表示，**树根是这个集合的代表**。每个元素只记录它的父亲 `fa[x]`。

- **查询 x 属于哪个集合**：沿着父亲一直往上走，走到根。
- **合并 x 和 y 的集合**：找到两个根，让一个根的父亲指向另一个根。

```
初始：每个人自成一个集合
fa: 1→1  2→2  3→3  4→4

合并(1, 2)：fa[1] = 2        2
                             |
                             1
合并(3, 4)：fa[3] = 4        4
                             |
                             3
合并(1, 3)：find(1)=2, find(3)=4, fa[2] = 4
          4
         / \
        3   2
            |
            1
```

## 3. 路径压缩

如果树变成一条长链，查询会很慢。**路径压缩**：查询时，把路径上所有点的父亲**直接改成根**。

```
查询 1 之前：1 → 2 → 4
查询 1 之后：1 → 4，2 → 4
```

## 4. 模板

```cpp
int fa[N];

void init(int n) {
    for (int i = 1; i <= n; i++) fa[i] = i;
}

int find(int x) {
    return fa[x] == x ? x : fa[x] = find(fa[x]);   // 路径压缩
}

void unite(int x, int y) {
    x = find(x); y = find(y);
    if (x != y) fa[x] = y;
}

bool same(int x, int y) {
    return find(x) == find(y);
}
```

加了路径压缩后，每次操作的均摊复杂度几乎是常数。（再加"按秩合并"可以更严格，但竞赛中一般只写路径压缩就够了。）

### 统计连通块个数

合并完后，有几个 `fa[i] == i` 的点就有几个集合。

### 例：亲戚（P1551）

n 个人、m 对亲戚关系、p 次询问。直接套模板。

## 5. 最小生成树

### 问题

n 个城市要修路连通，每条可能的路有一个造价。选一些路使所有城市连通，总造价最小。

选出的边一定构成一棵树（有环就能去掉一条边省钱），叫**最小生成树（MST）**，共 n - 1 条边。

### Kruskal 算法（推荐）

**贪心**：把所有边按权值从小到大排序，依次考虑。如果这条边的两个端点**还不连通**，就选它；否则跳过（选了会成环）。

判断连通用**并查集**。

```cpp
struct Edge { int u, v, w; };
vector<Edge> e;

long long kruskal(int n) {
    sort(e.begin(), e.end(), [](const Edge &a, const Edge &b) { return a.w < b.w; });
    init(n);
    long long total = 0;
    int cnt = 0;
    for (auto &[u, v, w] : e) {
        if (same(u, v)) continue;
        unite(u, v);
        total += w;
        if (++cnt == n - 1) break;
    }
    return cnt == n - 1 ? total : -1;   // -1 表示图不连通
}
```

复杂度 O(m log m)，主要是排序。

手推：

```
边：(1,2,1) (2,3,2) (1,3,3) (3,4,4) (2,4,5)
选 (1,2,1) ✓  选 (2,3,2) ✓  (1,3,3) 跳过（1、3 已连通）  选 (3,4,4) ✓
共 3 条边，总权 7
```

**为什么贪心是对的**：对于任何一个"割"（把点分成两部分），横跨两部分的最短边一定在某棵最小生成树里。Kruskal 每次选的边恰好是某个割的最短边。

### Prim 算法（了解）

从一个点开始，每次把"离已选集合最近"的点加进来。用堆优化是 O(m log n)，适合稠密图（用邻接矩阵 O(n²)）。

## 6. 例题精讲：修复公路（P1111）

每条公路在第 t 天修好，问最早第几天所有村庄连通。

按时间排序，依次合并，**合并到第 n-1 次时**的时间就是答案。这正是 Kruskal，只是"边权"换成了时间，求的是最大边权的最小值。

## 7. 例题精讲：买礼物（P1194）

买 B 件礼物，每件原价 A；买了第 i 件后再买第 j 件只要 K[i][j] 元。求最少花费。

建图：加一个"虚拟点 0"，0 到每件礼物连边权 A（原价购买）；i 和 j 之间连边 K[i][j]（如果 K = 0 表示没有优惠，不连或连 A）。求最小生成树。

> **虚拟源点**是常用技巧：把"直接选"变成"从虚拟点连过来的边"。

## 8. 例题精讲：无线通讯网（P1991）

P 个哨所，S 个卫星电话（有卫星电话的哨所之间无论多远都能通话），其余用无线电，所有无线电收发器的距离 D 相同。求最小的 D。

先求最小生成树，S 部卫星电话可以去掉 MST 中最大的 S - 1 条边。答案是 MST 中第 P - S 小的边（即去掉最大的 S-1 条后剩下的最大边）。

## 9. 易错点清单

1. 忘记 `init`（fa[i] = i）。
2. 合并写成 `fa[x] = y`（x、y 不是根）。必须先 find。
3. Kruskal 没判断图不连通。
4. 边数 m 很大时排序用了不稳定的比较函数（用 `<`，不要 `<=`）。
5. 递归 find 在极端情况下栈太深，可以改成迭代写法。

## 11. 自测

1. 并查集中"路径压缩"做了什么？
2. 一个 n 个点的连通图，最小生成树有几条边？
3. Kruskal 中，如果一条边两端已经连通，为什么要跳过？

<details><summary>答案</summary>

1. 查询时把路径上的每个点直接连到根上，以后查询更快。
2. n - 1 条。
3. 选它会形成环，去掉环上任意一条边仍连通，所以它是多余的（而且它比之前选的边都大）。

</details>
